# excel+ai=FilmMatch：胶片选购决策产品与运营分析项目

> 版本：MVP 产品与运营方案 v0.1  
> 产品定位：帮助胶片新手选择第一台适合自己的胶片相机。  
> 核心闭环：用户测评 → 相机推荐 → 相机对比/总成本计算 → 收藏 → 反馈 → 拍摄挑战与复访。

## 0. 研究结论与产品假设

本版基于 10 份有效问卷、现有 35 台相机数据和“真实价格版”推荐模型，样本量较小，以下结论用于 MVP 假设验证，不代表总体市场。

### 目标用户画像

| 维度 | 证据 | 产品含义 |
|---|---|---|
| 购买阶段 | 4 人正在考虑购买，4 人正在使用，2 人买过但少用 | 同时服务“决策前”和“买后复访”，但首要任务仍是首台机决策 |
| 胶片经验 | 3 人未真正接触，3 人 3 个月—1 年，3 人 1—3 年，1 人 3 年以上 | 默认用白话解释参数，提供“为什么推荐”而不是只给分数 |
| 预算 | 5 人 300 元以内，4 人 300—800 元，1 人 1,501—3,000 元 | 预算必须按机身 + 胶卷 + 冲扫的完整体验成本计算 |
| 操控 | 5 人希望完全自动，5 人可接受简单调节；相机类型为全自动/半自动各 5 人 | 推荐池优先自动对焦、自动曝光、内闪、轻便、低学习成本机型 |
| 拍摄动机 | 胶片色彩/质感 9 人，记录重要时刻 8 人，颗粒复古 7 人 | 结果页应先展示场景、效果和成功概率，再展示规格 |
| 场景 | 旅行 7 人；家人朋友 6 人；伴侣、风景各 5 人；主要拍人 5 人 | 推荐理由围绕“旅行/纪念/人像/日常”组织 |
| 风险担忧 | 不知道怎么选 5 人，二手成色难判断 5 人，不会手动 4 人 | 结果页必须有排除原因、验机提醒、故障风险和替代选项 |
| 内容触点 | 小红书 8 人，微信/朋友推荐 6 人 | MVP 以分享型测评结果卡和内容落地页作为拉新入口 |

### 一句话用户需求

“我想拍旅行、朋友和重要时刻，但不懂参数，也不想买到故障机；请告诉我在预算内最容易成功的第一台相机，以及第一次完整体验要花多少钱。”

## 1. 产品架构

### 1.1 用户端

1. **发现与入口层**：首页、场景入口、测评入口、内容/拍摄挑战入口。
2. **决策层**：用户测评、推荐结果、推荐解释、相机详情、相机对比、总成本计算。
3. **行动层**：收藏、购买/复核入口、二手验机清单、胶卷/冲扫建议。
4. **复访层**：拍摄挑战、拍摄记录、拍摄后反馈、失败原因复盘。

### 1.2 数据与规则层

1. **用户画像**：预算、操控偏好、拍摄场景、主体、光线、画面效果、便携性、新手偏好、风险接受度。
2. **相机主数据**：规格、价格区间、价格更新时间、自动化水平、便携性、新手适配分、维护风险、适合场景、推荐/不推荐理由。
3. **体验成本数据**：相机价格、胶卷单价、冲扫单价、电池/配件、风险缓冲。
4. **推荐服务**：硬门槛过滤、六维评分、排序、解释生成、模型版本记录。
5. **运营配置**：权重、价格容差、风险阈值、内容位、挑战任务、实验版本。

### 1.3 运营后台

1. 相机/胶卷/冲扫数据管理。
2. 推荐规则配置与版本发布。
3. 推荐结果质量监控：无结果率、低分率、被收藏率、反馈负向率。
4. 用户反馈审核与问题标签统计。
5. 漏斗、留存、场景和预算分群看板。
6. 拍摄挑战与内容运营管理。

## 2. 用户流程：优先打通完整闭环

### 2.1 主流程

1. **进入**：用户从小红书/微信/分享卡进入首页或直接进入测评。
2. **测评**：完成 8—10 个高信息量问题；支持进度保存，允许返回修改。
3. **推荐**：输出 Top 3，分别标注“最稳妥”“最符合场景”“最值得学习/升级”，同时给出不推荐项和原因。
4. **理解**：用户查看推荐解释、适合场景、上手难度、失败风险、二手验机重点。
5. **决策**：加入对比，查看总成本，点击购买/平台复核入口。
6. **收藏**：收藏相机、推荐组合和测评结果；生成可分享的结果卡。
7. **反馈**：收藏后立即收集轻反馈；购买/拍摄后收集“是否买了、是否拍摄、成片满意度、失败原因”。
8. **复访**：根据收藏机型和拍摄场景推荐 7 天拍摄挑战，完成后回填照片/评分，更新偏好与推荐解释。

### 2.2 关键状态

`未测评 → 已完成测评 → 已看推荐 → 已看详情 → 已对比/算成本 → 已收藏 → 已反馈 → 已参加挑战 → 已复盘`

MVP 的核心成功标准不是“看到了推荐”，而是至少完成：`完成测评 + 查看推荐详情 + 收藏 1 台相机 + 提交 1 次反馈`。

## 5. 推荐规则

### 5.1 现有模型可直接复用的规则

现有真实价格版已覆盖 35 台常见 35mm 胶片机，核心输入包括预算上限、操控偏好、主要场景、便携性、新手友好偏好和可接受维护风险。

**六维权重：**

| 维度 | 权重 | 评分要点 |
|---|---:|---|
| 预算匹配 | 25% | 价格中位与预算、价格区间与预算容差 |
| 操控适配 | 20% | 相机自动化水平与用户偏好距离 |
| 场景适配 | 20% | 适合场景是否命中主场景；未命中基础分 2/5 |
| 便携性 | 15% | 机身重量映射后的便携性分与用户偏好距离 |
| 新手友好 | 10% | 相机新手适配分与用户偏好距离 |
| 维护风险 | 10% | 相机维护风险与用户接受度距离 |

**硬门槛：**

1. 价格下限 > 用户预算上限 × 1.2：不适合。
2. 机型维护风险 > 用户可接受风险 + 1：不适合。
3. 加权总分 < 3/5：不进入推荐池。
4. 推荐结果不足 3 台时，展示“符合条件不足”的原因，并提供放宽一个条件的建议，不强行凑数。

**加权总分：**

`总分 = 预算匹配×0.25 + 操控适配×0.20 + 场景适配×0.20 + 便携性×0.15 + 新手友好×0.10 + 维护风险×0.10`

### 5.2 产品化后的输入映射

1. **预算**：问卷 Q5；默认以“第一次完整体验总预算”理解，不只看机身。
2. **操控**：Q13 手动接受程度 + Q15 相机类型偏好；自动/半自动用户优先 AF/AE/内闪。
3. **场景**：Q6 拍摄对象 + Q7 人/风景偏好 + Q8 记录/街拍/创作 + Q10 光线。
4. **便携**：Q14 体积重量、Q17 携带担忧、是否旅行高频。
5. **新手友好**：接触时长、是否看不懂参数、是否担心失败、是否希望简单操作。
6. **维护风险**：是否担心故障/成色/假货，以及是否愿意承担维修折腾。

### 5.3 推荐输出设计

每个用户只需要先理解 3 个结论：

1. **最稳妥**：预算与新手成功率优先。
2. **最符合场景**：旅行/人像/日常/街拍等用途优先。
3. **最值得学习**：保留一定手动空间，但明确学习与维护成本。

每台推荐必须展示：匹配分、命中维度、未命中维度、预计完整成本、二手风险、适合谁、不适合谁、替代机型。

### 5.4 总成本模型

`第一次完整体验成本 = 机身成交价 + 胶卷单价×拍摄卷数 + 冲扫单价×拍摄卷数 + 电池/基础配件 + 风险缓冲`

默认值可先采用问卷中的参考口径：冲扫 15—20 元/卷、富士 C200 73 元/卷；页面必须标注“市场参考价，会随渠道、成色和日期变化”。建议展示低/中/高三档，不用一个看似精确的数字误导用户。

## 6. 运营指标与看板

### 6.1 北极星指标

**首台相机决策闭环完成率 = 完成测评且收藏至少 1 台相机并提交反馈的用户数 ÷ 开始测评用户数**

这个指标同时约束推荐质量、解释质量和反馈设计，避免只追求测评完成量。

### 6.2 核心漏斗

| 阶段 | 指标 | MVP 目标假设 |
|---|---|---:|
| 进入 | 首页到测评点击率 | ≥ 35% |
| 开始 | 测评开始率 | ≥ 60% |
| 完成 | 测评完成率 | ≥ 70% |
| 推荐 | 结果页详情点击率 | ≥ 70% |
| 理解 | 详情/对比/成本工具使用率 | ≥ 35% |
| 决策 | 收藏率 | ≥ 25% |
| 反馈 | 收藏后轻反馈率 | ≥ 15% |
| 复访 | 7 日回访率 | ≥ 15% |
| 质量 | 无推荐结果率 | ≤ 5% |

以上是上线初期验证目标，不是问卷观测结果；上线后按渠道、预算、经验、场景分层复盘。

### 6.3 推荐质量指标

1. Top 1 详情点击率、Top 3 收藏率。
2. 推荐理由展开率、排除原因查看率。
3. 推荐后“不符合预期”率、风险相关负反馈率。
4. 推荐结果分数分布、机型曝光集中度、长尾机型点击率。
5. 价格过期率、缺少来源率、相机数据核验覆盖率。

### 6.4 运营看板分层

1. **经营层**：闭环完成率、周活用户、收藏用户、反馈用户、渠道贡献。
2. **产品层**：测评漏斗、结果页行为、对比/成本工具使用、页面退出点。
3. **规则层**：各维度得分、硬门槛淘汰、无结果、负反馈、规则版本对比。
4. **内容层**：场景入口点击、挑战参与率、分享率、内容带来的测评完成率。

## 7. 埋点方案

### 7.1 公共字段

`event_name`、`event_time`、`user_id`、`anonymous_id`、`session_id`、`page_id`、`source`、`assessment_id`、`recommendation_run_id`、`camera_id`、`position`、`rule_version`、`experiment_id`、`device_type`。

不采集原始 IP 作为业务画像；照片上传、文本反馈和联系方式必须单独取得授权，并设置删除能力。

### 7.2 事件表

| 事件 | 触发时机 | 关键属性 |
|---|---|---|
| `home_view` | 首页曝光 | 来源、落地模块 |
| `assessment_start` | 点击开始测评 | 入口、问卷版本 |
| `assessment_answer` | 提交每题 | 题目 ID、选项 ID、耗时、是否修改 |
| `assessment_complete` | 完成测评 | 耗时、完成题数、画像摘要 |
| `recommendation_view` | 结果页曝光 | run ID、结果数、Top 1 相机 |
| `recommendation_explain_view` | 查看理由/排除原因 | 相机、理由类型 |
| `camera_detail_view` | 查看详情 | 相机、排名、来源页面 |
| `compare_add/remove` | 加入/移出对比 | 相机、对比集合、顺序 |
| `compare_view` | 打开对比页 | 相机列表、差异字段 |
| `cost_calculate` | 计算总成本 | 卷数、胶卷、冲扫、档位 |
| `favorite_add/remove` | 收藏/取消收藏 | 对象类型、对象 ID、入口 |
| `feedback_submit` | 提交反馈 | 阶段、评分、标签、是否购买/拍摄 |
| `purchase_link_click` | 点击购买/复核 | 平台、相机、价格快照 |
| `challenge_view/join/submit` | 挑战浏览/参加/提交 | 主题、场景、完成状态 |
| `return_visit` | 回访 | 回访天数、最近收藏、最近挑战 |

### 7.3 埋点验收

1. 每次推荐结果必须能追溯到 `assessment_id + run_id + rule_version`。
2. 收藏、反馈必须能追溯到具体 `camera_id` 和推荐位置。
3. 价格展示必须记录 `price_snapshot_id`，支持解释“当时为什么是这个成本”。
4. 事件去重键建议为 `user_id + event_name + client_event_id`。
5. 上线前用 3 条固定测试路径验收：低预算自动用户、旅行人像用户、手动学习用户。

## 8. MVP 范围

### 8.1 必须做

1. 移动端首页和测评入口。
2. 8—10 题测评，覆盖预算、操控、场景、便携、新手、风险。
3. 基于 35 台相机的数据与现有六维模型输出 Top 3。
4. 推荐解释、排除原因、价格更新时间、基础二手验机提醒。
5. 相机详情、最多 3 台对比、第一次完整体验总成本计算。
6. 收藏夹和简单反馈闭环。
7. 相机数据、价格快照、规则配置、推荐运行记录。
8. 核心漏斗与推荐质量埋点、基础运营看板。

### 8.2 可做但不阻塞上线

1. 胶卷推荐 3—5 款基础库。
2. 购买渠道链接和冲扫建议。
3. 结果卡分享、小红书/微信落地页。
4. 规则 A/B 测试和分群权重。

### 8.3 暂不做

1. 真实库存和成交价实时抓取。
2. 平台交易、担保和售后。
3. 完整 AI 问答助手。
4. 大规模用户照片社区和复杂内容审核。
5. 全量胶卷数据库、冲扫店评分体系。

## 9. MVP 验收标准

1. 用户可以在 3 分钟内完成测评并获得至少 1 个可解释推荐。
2. 推荐结果中的每台相机都有价格区间、更新时间、至少 1 条推荐理由和 1 条风险提醒。
3. 用户可以从推荐直接进入详情、对比、总成本、收藏和反馈，不丢失上下文。
4. 无推荐结果时，系统给出明确的放宽条件，而不是空白页。
5. 运营人员可以不改代码地调整权重、预算容差和风险阈值，并保留规则版本。
6. 每一次推荐、收藏和反馈都能回溯到同一用户测评与规则版本。

## 10. 第一阶段落地顺序

**第 1 周：** 固化问卷字段、相机字段、价格快照和规则版本；完成测评题目与埋点字典。  
**第 2 周：** 完成测评、推荐结果、详情、对比、总成本、收藏。  
**第 3 周：** 接入反馈、验机提示、基础看板和推荐质量监控。  
**第 4 周：** 用低预算自动、旅行人像、手动学习三类路径做可用性测试，调整权重和文案。  

优先级判断：先让用户“做完、看懂、收藏、反馈”，再扩展胶卷、挑战和 AI 问答；否则运营数据无法判断问题到底出在推荐质量还是功能复杂度。

## 11. 数据来源与边界
